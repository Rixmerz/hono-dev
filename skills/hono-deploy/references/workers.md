## Files

`examples/workers/wrangler.jsonc` is a real file. Cloudflare recommends `wrangler.jsonc` for new
projects (some newer features exist only there).

```ts file=src/index.ts
import { Hono } from "hono";
import * as z from "zod/v4";

// Bindings and secrets arrive per request as c.env, never as module-level globals.
// CloudflareBindings is generated by `wrangler types --env-interface CloudflareBindings`.
const app = new Hono<{ Bindings: CloudflareBindings }>();

const envSchema = z.object({
	ENVIRONMENT: z.enum(["production", "staging", "development"]),
	API_TOKEN: z.string().min(16),
});

// Workers have no startup phase, so validate on the first request of each
// isolate. Deploying new secrets creates a new version, so one pass per isolate
// is enough.
let envChecked = false;
app.use("*", async (c, next) => {
	if (!envChecked) {
		const parsed = envSchema.safeParse(c.env);
		if (!parsed.success) {
			console.error(z.prettifyError(parsed.error));
			return c.json({ error: "misconfigured" }, 500);
		}
		envChecked = true;
	}
	await next();
});

app.get("/healthz", (c) => c.text("ok"));

app.put("/kv/:key", async (c) => {
	await c.env.CACHE.put(c.req.param("key"), await c.req.text());
	return c.body(null, 204);
});

app.get("/kv/:key", async (c) => {
	const value = await c.env.CACHE.get(c.req.param("key"));
	return value === null ? c.notFound() : c.text(value);
});

app.get("/whoami", (c) => c.json({ environment: c.env.ENVIRONMENT }));

export default app;
```

`.dev.vars` (local secrets, dotenv syntax, same directory as the Wrangler config):

```sh
API_TOKEN=local-dev-token-0123456789
```

Both `.dev.vars` and `.env` "should not be committed to git":

```
.dev.vars*
.env*
```

Use `.dev.vars` or `.env`, not both: if `.dev.vars` exists, `.env` is ignored.

## Types

```sh
wrangler types --env-interface CloudflareBindings
```

writes `worker-configuration.d.ts`. The Hono docs say to pass `--env-interface` "to avoid a naming
collision with Hono's built-in `Env` type". Re-run it after every change to `wrangler.jsonc`;
`wrangler types --check` exits 1 when the file is stale, which suits CI. Include the generated
file in `tsconfig.json` (`"include": ["src/**/*.ts", "worker-configuration.d.ts"]`).

## Commands

```sh
wrangler dev --local --port 8787          # runs locally, remote bindings off; --remote uses a preview environment
wrangler deploy --dry-run --outdir out    # compile without deploying
wrangler deploy                           # --env <name> for a named environment
wrangler secret put API_TOKEN             # prompts, or reads piped stdin; creates a version AND deploys it
wrangler secret list --format json
wrangler secret bulk secrets.json         # up to 100 per command; JSON or .env
wrangler versions secret put API_TOKEN    # version only, for gradual deployments
wrangler tail                             # live logs; --status error, --search <text>
```

`wrangler secret` accepts `--env <name>` (global flag). Local development uses `.dev.vars`, not
the vault.

## Rules and traps

| Trap | What to do |
|---|---|
| `compatibility_date` newer than the installed workerd | `wrangler dev` fails with "This Worker requires compatibility date ... but the newest date supported by this server binary is ...". It happened with `2026-10-31`, the date in Cloudflare's own configuration example, against workerd 1.20261023.1 (newest supported `2026-10-30`). Use a date the installed workerd supports |
| `nodejs_compat` | for dates `2024-09-23` to `2026-08-03` you must add the flag; from `2026-08-04` both `nodejs_compat` and `nodejs_compat_v2` are on by default (`no_nodejs_compat` / `no_nodejs_compat_v2` switch them off). With it enabled, secrets are also readable from `process.env` |
| Bindings read at module load | read them from `c.env` inside the request; Hono's docs show the same for `basicAuth` and the other auth middlewares: build them inside `app.use` |
| Secrets in `vars` | `vars` is plain text in the config. Use `wrangler secret put` |
| `env.<name>` blocks | bindings such as `vars`, `kv_namespaces`, `r2_buckets` are not inherited: define them in each environment (the page's list does not mention `d1_databases`; define it per environment to be safe) |
| `kv:namespace` | the old `kv:...` command form is deprecated; use `wrangler kv namespace create <NAMESPACE>` |
| No startup phase | validate `c.env` on the first request of each isolate, as `src/index.ts` does; new secrets mean a new version, so one pass per isolate is enough |

## Ask the project first

`hono_project(workspace="/abs/path")` reports the runtime and `deployTargets`.
`hono_validate(workspace="/abs/path", categories=["conventions"])` covers `C001`: `process.env` on
Workers without `nodejs_compat`, `Deno.env` under Node, `c.env` on Node. Note that from
`compatibility_date` 2026-08-04 `nodejs_compat` is on by default, so a rule that looks only for the
flag would flag code that works (not verified against the rule: the validators did not exist when
this was written).
